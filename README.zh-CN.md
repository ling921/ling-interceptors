# Ling.Interceptors

[English](README.md) | 简体中文

[![Build](https://github.com/ling921/ling-interceptors/actions/workflows/build.yml/badge.svg)](https://github.com/ling921/ling-interceptors/actions/workflows/build.yml)
[![NuGet](https://img.shields.io/nuget/v/Ling.Interceptors.svg)](https://www.nuget.org/packages/Ling.Interceptors/)

`Ling.Interceptors` 是一个 Roslyn 分析器和增量源生成器，基于 C# Interceptors 在编译期替换或监控指定的方法调用点。要求使用 .NET SDK 9.0.200 或更高版本。

## NuGet 包

| 包 | 用途 |
| --- | --- |
| [`Ling.Interceptors`](src/Ling.Interceptors/README.zh-CN.md) | 公开拦截和监控 API，以及内置分析器、源生成器与构建集成。 |
| `Ling.Interceptors.Logging` | `Microsoft.Extensions.Logging` sink。 |
| `Ling.Interceptors.Console` | 输出 JSON Lines 到标准错误的 sink。 |
| `Ling.Interceptors.OpenTelemetry` | `ActivitySource` 与 `Meter` sink。 |

## 安装

```shell
dotnet add package Ling.Interceptors
```

包会自动将 `Ling.Interceptors.Generated` 加入 `InterceptorsNamespaces`，消费项目无需手写该属性。

## 方法监控

监控运行时契约、默认空 sink 与默认值格式化器均包含在 `Ling.Interceptors` 中；主包不依赖 `System.Text.Json`。

在目标方法上标记即可，generator 会在当前 compilation 中寻找调用点并自动生成 wrapper：

```csharp
[Monitor(CaptureParameters = true, CaptureReturnValue = true)]
[return: SensitiveData]
public async Task<Order> PlaceOrder(
    int customerId,
    [SensitiveData] string product)
{
    // implementation
}
```

`SensitiveData` 与 `Monitor` 独立。敏感字符串会部分隐藏，其他敏感值会在进入 sink 前被完全隐藏。参数和返回值默认不采集；异常与耗时默认采集。

sink 必须由应用显式配置，默认不会输出：

```csharp
MonitorRuntime.Sink = new LoggerMonitorSink(loggerFactory);
// 或：new ConsoleMonitorSink()
// 或：new OpenTelemetryMonitorSink()
```

默认 Formatter 会保留标量值、掩码敏感值，并将其他对象表示为声明类型摘要；它不会调用 `ToString()` 或序列化复杂对象。需要结构化输出时可设置 `MonitorRuntime.Formatter` 为自定义 Formatter，`MonitorValueContext.IsSensitive` 用于标识不得泄露的值。

引用程序集内部已经编译好的调用点不会被修改。声明受监控方法和调用受监控方法的项目都需要引用 `Ling.Interceptors`。

## 使用方式

声明一个静态替换方法。第二个构造参数必须是限定形式的 `nameof(T.Method)`，Scope 为必填参数。

```csharp
using Ling.Interceptors;

internal sealed class Service
{
    internal void Send(string value) => Console.WriteLine($"original:{value}");
}

internal static class Replacements
{
    [Intercept("trace", nameof(Service.Send),
        InterceptionScope.Explicit | InterceptionScope.Compilation)]
    internal static void Send(Service service, string value)
    {
        Console.WriteLine($"trace:{value}");
        service.Send(value); // 直接调用原始实现
    }
}
```

调用点可以显式选择某条规则；也可以由 `Compilation` 覆盖当前项目的普通调用：

```csharp
service./* intercept:trace */Send("one"); // 显式替换
service.Send("two");                      // Compilation 替换
```

## Scope

| Scope | 语义 |
| --- | --- |
| `Explicit` | 允许调用点通过 `/* intercept:id */` 选择此规则。 |
| `Compilation` | 拦截当前 compilation 内匹配的普通方法调用。 |
| `GeneratedCode` | 扩展 `Compilation` 规则，使其包含生成代码；当存在其他源生成器输出时启用两阶段构建。 |
| `None` | 禁用该规则。 |

`GeneratedCode` 必须与 `Compilation` 组合使用。显式规则优先于 compilation 规则。替换方法体及其 lambda/local function 内的调用会被排除，因此替换方法可安全调用原始实现。

## 边界

- 替换方法必须是 internal 或 public 的静态方法，且签名与目标方法兼容。
- 目标可位于当前项目或引用程序集；不能修改已编译 DLL 内部的调用。
- 不支持构造函数、属性、运算符、委托调用和方法组转换。
- v1 仅支持在当前 compilation 中定义规则和替换方法。
- 方法监控支持普通返回值、`Task`、`Task<T>`、`ValueTask` 和 `ValueTask<T>`；暂不支持 ref-return 方法。

## 生成代码与两阶段构建

`Compilation | GeneratedCode` 会识别常规生成文件（`<auto-generated>`、`.g.cs`、`.generated.cs`、`.designer.cs`）与 `GeneratedCodeAttribute`。在命令行 Build、Pack、Publish 中，包会物化其他源生成器输出并执行最终编译，从而拦截同一轮生成代码中的调用。设计时构建只提供预览，不启动嵌套编译。

## 示例

每个 sample 都是一个可独立运行的小型应用，用于展示实际集成方式，而不是测试项目。

- **[基础拦截与监控](samples/Ling.Interceptors.Sample)** — 从显式和 compilation 范围的 `[Intercept]` 规则开始，并通过 `ConsoleMonitorSink` 演示同步、`Task`、`ValueTask` 的 `[Monitor]` 方法。
  运行：`dotnet run --project samples/Ling.Interceptors.Sample`
- **[NuGet 包与两阶段构建](samples/Ling.Interceptors.PackSample)** — 消费本地打包的 `Ling.Interceptors` NuGet 包，并演示拦截由另一 source generator 生成的调用。
  运行：`dotnet run --project samples/Ling.Interceptors.PackSample`
- **[`ILogger` 集成](samples/Ling.Interceptors.LoggingSample)** — 使用控制台日志提供程序配置 `LoggerMonitorSink`，展示结构化输出和经过脱敏的方法参数。
  运行：`dotnet run --project samples/Ling.Interceptors.LoggingSample`
- **[OpenTelemetry 集成](samples/Ling.Interceptors.OpenTelemetrySample)** — 配置 `OpenTelemetryMonitorSink`，并通过原生 `ActivityListener` 和 `MeterListener` 展示追踪与耗时指标；示例不绑定特定 SDK exporter。
  运行：`dotnet run --project samples/Ling.Interceptors.OpenTelemetrySample`
- **[跨程序集监控](samples/Ling.Interceptors.CrossAssembly.Caller)** — 将 `[Monitor]` API 放在被引用的目标程序集，仅在调用方安装 generator，展示常见的消费者项目结构。
  运行：`dotnet run --project samples/Ling.Interceptors.CrossAssembly.Caller`

## 开发

- 构建：`dotnet build Ling.Interceptors.slnx`
- 在 .NET 9 和 .NET 10 测试：`dotnet test Ling.Interceptors.slnx`
- 打包：`dotnet pack src/Ling.Interceptors/Ling.Interceptors.csproj -c Release`
